# Project Specifications

This directory contains project-specific specifications organized by business domain. Use stable, descriptive names rather than dates or authoring-tool labels.

Each specification should identify its purpose and status, then separate functional scope, non-functional requirements, domain concepts, interfaces, technical design, validation, and open questions as appropriate. Split functional and technical documents when they have different audiences or change independently; link related documents from the domain index.

For a worked example that carries the data-platform design through all six Delivery Framework stages into code, AWS options, deployment, and operations, see the [end-to-end walkthrough](../examples/end-to-end/README.md).
