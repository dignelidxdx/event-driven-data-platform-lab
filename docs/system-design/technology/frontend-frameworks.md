# Frontend Frameworks

Select a frontend framework based on interaction complexity, rendering and delivery needs, accessibility, team expertise, ecosystem, and long-term maintenance. The choices below are examples to investigate, not endorsements.

| Framework or approach | Potential fit | Trade-offs to investigate |
|---|---|---|
| React | Component-driven interactive applications and broad ecosystem needs | Library leaves routing and application structure choices to the team; ecosystem options require evaluation |
| Next.js | React applications needing integrated server rendering or full-stack web features | More runtime and framework concepts; deployment and caching behavior require understanding |
| Vue | Progressive adoption or component-oriented applications | Ecosystem and team availability may differ by organization; framework conventions still need alignment |
| Angular | Applications that benefit from an integrated framework and strong conventions | Larger framework surface and learning investment |
| Svelte / SvelteKit | Applications where compiler-based components or integrated web application features fit | Smaller ecosystem in some contexts; validate libraries, hiring, and hosting support |

Compare accessibility support, client and server rendering, routing, data loading, testing, bundle behavior, deployment, and upgrade policy. Build a representative screen and trace its API interaction before committing to a choice.
