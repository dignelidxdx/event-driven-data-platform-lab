# System Design Document Template

## Summary

State the problem, proposed solution, principal trade-offs, and requested decision.

## Context and scope

Link the requirements brief. Identify stakeholders, system boundary, exclusions, constraints, and assumptions.

## Requirements and workload

Summarize functional behavior, quality goals, workload estimates, and evidence or uncertainty.

## Domain and data

Describe core concepts, ownership, invariants, data lifecycle, and relevant domain boundaries.

## Interfaces and data flow

Link API and event contracts. Include key workflow diagrams and failure behavior.

## Architecture

Link C4 diagrams. Explain components, responsibilities, dependencies, and deployment assumptions.

## Alternatives and decisions

Summarize options and trade-offs; link RFCs and ADRs.

## Deep dives

Cover only material concerns such as capacity, consistency, security, reliability, query performance, and operations.

## Validation, risks, and delivery

List evidence, unresolved risks and owners, rollout or migration approach, and stakeholder decisions needed.

## References

Link related requirements, contracts, diagrams, experiments, and implementation areas.
