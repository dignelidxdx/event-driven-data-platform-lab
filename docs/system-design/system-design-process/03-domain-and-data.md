# Domain and Data

Understand the business concepts, ownership boundaries, lifecycle rules, and information the system must retain or exchange. Identify authoritative sources of data and distinguish operational state from derived views.

Use DDD techniques such as shared vocabulary and bounded-context exploration when they help resolve domain ambiguity. Model entities, value objects, invariants, and domain events before choosing a database schema. See the Delivery Framework's [Core entities](../delivery-framework/02-core-entities.md) and [Data flow](../delivery-framework/04-data-flow.md) stages.

Sketch data relationships and lifecycle transitions. Record retention, privacy, consistency, and access needs for the later architecture and deep dives.
