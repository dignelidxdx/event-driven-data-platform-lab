# Options and Trade-offs

Develop a small set of plausible options that satisfy the stated requirements. Compare them against the quality goals, workload, team skills, delivery constraints, operating cost, and expected evolution.

Technology selection belongs here: compare languages, frameworks, storage, and infrastructure using explicit criteria rather than popularity alone. The [technology guide](../technology/README.md) provides comparison and onboarding references. For example, compare Go and Java in the context of runtime characteristics, compile and build workflow, ecosystem, concurrency model, team familiarity, and operational needs; validate claims against the actual workload and team.

Use an RFC when several stakeholders should discuss a proposal before commitment. After deciding, record material choices, alternatives, and consequences in an [ADR](../artifacts-and-templates/architecture-decision-record.md). Keep the decision traceable to the requirements it serves.
